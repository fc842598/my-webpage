# 天纪元堂样本矩阵
整理时间：2026-04-03

目的：
- 只为“元堂定位”补真值样本
- 不再混入年卦问题
- 把当前已覆盖样本和仍缺的关键盘型明确列出来

---

## 1. 这份矩阵要解决什么

当前问题已经缩小到：

- `四柱 -> 先天卦` 基本稳定
- `先天卦 -> 元堂 -> 后天卦` 还会在新盘上偏离 `天纪.exe`

所以这份矩阵只抓四个核心字段：

1. 四柱
2. 先天卦
3. 元堂爻
4. 后天卦

只要这四项能大量对齐，后面再修年卦才有意义。

---

## 2. 每条样本必须记录什么

最小记录格式：

```text
公历/农历：
出生时间：
地点：
性别：
民用时段：早子 / 夜子 / 丑 / 寅 / ...

四柱：
先天卦：
元堂爻：
后天卦：
```

建议再额外补这几个派生字段，方便后面归类：

- `hourGroup = upper-six / lower-six`
- `ziKind = early-zi / night-zi / none`
- `isThreeZizun = true / false`
- `monthLing = yang / yin`
- `personPolarity = yang / yin`

- `lower-six`

未均衡：

- `upper-six / non-zi` 目前只有 1 条，而且是女命

- 女命目前没有 `lower-six` 真值样本

- `early-zi` 男

### 4.4 按卦型

- 三至尊卦中的 `坎为水`
- 三至尊卦中的 `水山蹇`

缺口：

- 三至尊卦中的 `水雷屯`

## 5. 现在最关键的缺口

按优先级排，最应该补的是这 6 类：

1. `女命 + lower-six`
   - 现在几乎空白
   - 无法判断女命在下六时是否仍按当前实现落阴爻池

2. `男命 + upper-six + 非子时`
   - 当前只明确了男命 `子时`
   - 对 `丑寅卯辰巳` 的泛化还不够

3. `女命 + early-zi`
   - 现在只有女命 `night-zi`
   - 无法确定 `早子/夜子` 对女命是否真同规则

4. `三至尊卦 + 水雷屯`
   - 当前三至尊只碰到了 `坎为水`、`水山蹇`
   - `水雷屯` 没有真值样本，无法排除软件还有额外边界

5. `upper-six / non-zi` 的多卦型覆盖
   - 当前只有 `辰时` 这一条
   - 不足以说明 `upper-six` 非子时全组都没分支

6. `女命 + lower-six + three-zizun`
   - 这是最可能藏软件边界的地方
   - 现在完全没有样本

## 6. 建议的最小补样本包

如果只想用最少成本把元堂问题继续压缩，建议下一轮至少补这 8 条：

1. 女，`早子`，普通卦
2. 女，`早子`，三至尊卦
3. 女，`申/酉/亥` 任一，普通卦
4. 女，`申/酉/亥` 任一，三至尊卦
5. 男，`丑/寅/卯/巳` 任一，普通卦
6. 男，`丑/寅/卯/巳` 任一，三至尊卦
7. 任意性别，先天卦明确为 `水雷屯`
8. 任意性别，和现有 `1991-02-16` 类似，只改时段不改日期，做同日跨时对照

这 8 条补完后，至少能回答：

- `子时` 特例是不是只对子时成立
- `命阴阳` 是否真正进入元堂分支
- `水雷屯` 是否和另外两至尊一致
- `upper-six` 非子时到底是不是还能继续沿用当前规则

## 8. 对当前项目的直接建议

在元堂样本矩阵没补够之前，不建议再对“元堂主算法”做大改。  
更稳的顺序是：

1. 保持 [generator.js](C:/Users/1/Desktop/家里用的图标/src/ziping/generator.js) 当前元堂结构不大动。
2. 先用这份矩阵补真值。
3. 样本一旦出现系统性偏差，再改 `getYuanTangDetail(...)`。

否则很容易再次出现：

- 修对 7 条旧样本
- 新盘又错
- 但不知道错在 `元堂`、`后天卦` 还是 `年卦`

这种循环。
