# 每天固定20篇紫微文章

自2026-10-26起，每天按北京时间完成20篇新的中文紫微文章及20篇英文改写。英文版不另计内容篇数。新要求覆盖旧的“最多20篇”和“发1篇也算当天批次完成”的处理。

## 固定顺序：先搜同行，再更新文章

复用研究任务`20`和发布任务`ai`，不得新建重复任务或绕过前置检索。

1. 07:15唤醒电脑并确保Codex运行。
2. 研究任务07:30开始；08:30仅在当天报告未就绪时补检索。先读研究记忆、历史记录和近30天报告，再真实搜索、打开正文，按URL、标题、主题、主旨去重。
3. 写完当天研究卡、完整裸链接清单及历史记录后，运行研究完成检查，生成当天交接状态。候选不足20篇如实写实际数量和原因，不凑数、不把摘要核验当成正文证据。
4. 发布任务先检查当天报告及交接状态。缺失、仍在检索、历史记录不一致或交接后文件变化时，先完成或修复研究，再写稿发布；不得默认使用旧报告。
5. 结合同行研究和用户同步文稿确定20个原创搜索问题；再与站内标题、开头、例子和搜索意图查重。工作说明记录各slug参考的研究日期、原文URL、采用角度和与旧文区别，文章正文不带来源痕迹，不照搬同行结构和文句。
6. 完成20篇中文及英文改写、SEO与集合资源同步、本地验证、推送和线上核验后，才计入当天完成数量。

研究来源数量与原创文章数量分别统计。10篇合格来源可以支持多个不同的原创问题；不能虚构另10篇来源，也不能把同一篇内容换标题凑成20篇文章。正文证据和主旨去重仍需编辑核验，脚本检查不能替代这两项工作。

## 研究交接检查

研究任务使用桌面安装的独立检查工具，不修改网站代码：

```powershell
node C:/Users/1/Desktop/找同行/工具/check-daily-peer-research.mjs --date 2026-10-26 --mode begin
# 完成真实检索、报告及历史记录后：
node C:/Users/1/Desktop/找同行/工具/check-daily-peer-research.mjs --date 2026-10-26 --mode complete
node C:/Users/1/Desktop/找同行/工具/check-daily-peer-research.mjs --date 2026-10-26 --mode check
```

日期必须换成当天北京时间日期。`begin`会标为检索中；`complete`仅在文件结构、原始链接、历史记录一致和精确URL/标题/主题去重通过后写就绪状态；`check`核对当天状态及报告、历史文件的内容指纹。交接文件为桌面找同行目录的`同行检索状态-YYYY-MM-DD.json`。

生产发布器处理`ziwei-daily-YYYY-MM-DD-queue.md`时，强制执行当天交接检查，未通过会在写公开文章页之前停止。`--output-root`隔离预览不发布，不受此限制；不得用改队列名称或手工写文章页绕过正式任务流程。

## 现有发布自动化 ai

- 09:00：读取远端，确认当天研究就绪，再去重、准备并发布当天20篇。
- 10:00、11:00、12:00、16:00、20:00：检查当天数量，补足缺口；达到20篇就只复查，不重复发。
- 14:00、19:00：保留只读核验，不在这两个时段新增文章。
- 21:00：补缺并核验当天20篇；基于已完成的研究准备次日20篇中英文草稿及队列，标为待次日复核，不提前生成公开文章页或计为已发布。
- 22:00：兜底补缺及末次验收，覆盖当天较晚恢复或上一轮失败的情况。

次日正式发布前，必须先完成次日的同行检索，用次日研究重新核对备稿选题和站内重复情况。备稿现成不能成为跳过检索的理由。

复用同一个自动化，不新建重叠的发布任务。若某篇重复或不合格，替换该篇选题后继续处理其余文章。保留原有文章写作、SEO、上线复查规则；数量要求不能靠复制正文、回填发布日期或重复URL凑数。

## 数量检查

先在干净隔离工作树中拉取最新origin/master，再执行：

```powershell
git -c http.proxy= -c https.proxy= fetch origin master
node scripts/check-daily-article-quota.mjs --date 2026-10-26 --output daily-quota.json
```

`--date`必须替换为执行当天的北京时间日期。检查器读取远端提交历史，只统计当天新增路径且Article发布日期属于当天的中文文章；旧稿改日期、补发旧日期稿、栏目页均不填当天名额。每篇对应英文页必须存在，线上title、canonical、Article headline/datePublished必须一致。双语索引、Feed和三个sitemap也必须与远端版本同步。

- 退出码0：当天恰好20篇，双语与集合资源在线核验通过。
- 退出码1：未达标、超量或线上验证失败。
- 退出码2：Git、参数或执行环境错误。
- `remainingToPublish`：还需要新增的中文主题数；已存在但缺英文的文章应修复英文，不新增第21个主题。

发布前看数量，发布后再次运行。只在退出码0时报告“当天20篇完成”。未达标必须写清实际数量、缺口、失败项与原因，不能把1/20写成完成。状态记录仍使用桌面找同行目录的每日文章状态文件。

## 主机可用性

本机Windows辅助任务`YuetianAI-Article-Host-Wake`每天07:15唤醒电脑并确保Codex桌面程序运行，早于07:30同行检索。只负责主机可用性，不另建文章发布循环。

脚本安装在`%LOCALAPPDATA%\YuetianArticleSchedule\wake-daily-article-host.ps1`。任务需启用WakeToRun、StartWhenAvailable及失败重试；保留原有午夜锁屏休眠。交流电唤醒定时器应启用。

本地自动化仍依赖电脑通电、登录会话、网络、应用和账户额度。唤醒任务不能启动已完全关机的电脑；关机期间也要发布，需要另行把执行环境迁移到常在线服务器。没有迁移服务器时，不得声称不受电脑开关机影响。
