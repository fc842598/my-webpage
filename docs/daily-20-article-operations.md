# 每天固定20篇紫微文章

自2026-10-26起，每天按北京时间完成20篇新的中文紫微文章及20篇英文改写。英文版不另计内容篇数。新要求覆盖旧的“最多20篇”和“发1篇也算当天批次完成”的处理。

## 现有自动化 ai

- 09:00：读取远端、去重、准备并发布当天20篇。
- 10:00、11:00、12:00、16:00、20:00：检查当天数量，补足缺口；达到20篇就只复查，不重复发。
- 14:00、19:00：保留只读核验，不在这两个时段新增文章。
- 21:00：最后补缺并核验当天20篇，再准备次日20篇完整中英文稿件及队列。次日稿此时不生成公开文章页、不提前标记已发布。

复用同一个自动化，不新建重叠的发布任务。若某篇重复或不合格，替换该篇选题后继续处理其余文章。保留原有文章写作、SEO、上线复查规则；数量要求不能靠复制正文、回填发布日期或重复URL凑数。

## 数量检查

先在干净隔离工作树中拉取最新origin/master，再执行：

```powershell
git -c http.proxy= -c https.proxy= fetch origin master
node scripts/check-daily-article-quota.mjs --date 2026-10-26 --output daily-quota.json
```

`--date`必须替换为执行当天的北京时间日期。检查器读取远端提交历史，只统计当天新增路径且Article发布日期属于当天的中文文章；旧稿改日期、补发旧日期稿、栏目页均不填当天名额。每篇对应英文页必须存在，线上title、canonical、Article headline/datePublished必须一致。双语索引、Feed和三个sitemap也必须与远端版本同步。

- 退出码0：当天恰好20篇，双语与集合资源在线核验通过。
- 退出码1：未达标、超量或线上验证失败。
- 退出码2：Git、参数或执行环境错误。
- `remainingToPublish`：还需要新增的中文主题数；已存在但缺英文的文章应修复英文，不新增第21个主题。

发布前看数量，发布后再次运行。只在退出码0时报告“当天20篇完成”。未达标必须写清实际数量、缺口、失败项与原因，不能把1/20写成完成。状态记录仍使用桌面找同行目录的每日文章状态文件。

## 主机可用性

本机Windows辅助任务`YuetianAI-Article-Host-Wake`每天08:45唤醒电脑并确保Codex桌面程序运行。只负责主机可用性，不另建文章发布循环。

脚本安装在`%LOCALAPPDATA%\YuetianArticleSchedule\wake-daily-article-host.ps1`。任务需启用WakeToRun、StartWhenAvailable及失败重试；保留原有午夜锁屏休眠。交流电唤醒定时器应启用。

本地自动化仍依赖电脑通电、登录会话、网络、应用和账户额度。唤醒任务不能启动已完全关机的电脑；关机期间也要发布，需要另行把执行环境迁移到常在线服务器。没有迁移服务器时，不得声称不受电脑开关机影响。
