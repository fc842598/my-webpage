# 2026-04-18 AI半仙前端修复（前端）

## 1. 本次目标

- 修复进入 AI半仙 tab 时报 `Unexpected token '<'`（服务器返回 HTML 404 而非 JSON）
- 进 tab 时立即触发 Memory A 预建，不等用户发第一句话
- 检测命盘切换（同页面重新排盘），自动重置对话会话
- 友好化错误提示（非 JSON 响应时显示可读错误而非白屏或控制台报错）

---

## 2. 实际完成内容

### 2.1 POST 初始化 + 命盘切换检测
`js/ai-chat.js` 中 `init()` 函数改为：

- 新增 `_lastChartRecordId` 变量：每次 init 时对比当前 `window._chartRecordId`，不同时清空 `_sessionId` / `_initialized`，强制重新建立会话。
- 组装 `chartData`（调 `buildChartPayload()`），有 chartData 时用 **POST** 请求 `/api/ai/chat/session`（body 含 chartData），触发后端 eager Memory A 建档；无 chartData 时降级为 **GET**（兼容极端情况）。
- 响应含 `memoryAJustBuilt: true` 时，在消息流中插入系统提示"✦ 命盘总档已建立，许半仙已完整读取您的命盘。"

### 2.2 非 JSON 响应友好处理
fetch 之后增加检查：
```javascript
if (!r.ok && r.headers.get('content-type').indexOf('application/json') === -1) {
  throw new Error('服务器返回 ' + r.status + '，请稍后重试');
}
```
Railway 冷启动期间返回 HTML 502/404 时，用户看到"服务器返回 502，请稍后重试"而非控制台 JSON parse 报错。

## 6. 已知问题

- **Railway 冷启动延迟**：首次进 tab 时后端可能需要 5–15 秒唤醒，期间 loading bar 持续显示；预热 ping（`_warmUp`）在页面加载 2 秒后触发，可缩短等待，但不能完全消除。
- **`buildChartPayload` 时序**：`buildChartPayload()` 依赖 `window._chart`，若用户刚打开页面尚未排盘即点 AI半仙 tab，会走入"请先完成排盘"分支而非报错，行为正确。
- **`_lastChartRecordId` 跨 tab 不持久**：刷新页面后 `_lastChartRecordId` 清零，不影响逻辑（刷新后会重新 init），但如果想持久化可考虑 sessionStorage。

## 8. 下一步建议

1. **端到端冒烟**：Railway 部署完成后（约 2–5 分钟），手动测试：
   - 排盘 → 进 AI半仙 tab → 确认 loading bar 消失、badge 显示"命档 已建立"
   - 发一条消息，确认许半仙正常回复
   - 不刷新页面，重新输入另一个人的信息重新排盘 → 再进 AI半仙 tab，确认会话重置、新命盘信息被读取
2. **`_warmUp` 改为 POST session**：目前预热 ping 发的是 `GET session?chartRecordId=__ping__`（会建一条无效 session），可改为只 GET 一个轻量健康检查接口（如 `/api/ai/run` 不带参数的 OPTIONS），避免建垃圾 session 记录。
3. **Memory A stale 刷新 UI 优化**：`_chatInvalidateMemoryA()` 把 badge 改为"命档 待更新"，但不会主动触发重建；可考虑下次进 tab 时（`init` 时）如果检测到 stale 且 chatData 可用，直接 POST 重建，而不是等到下一条消息。
