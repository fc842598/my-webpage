## 1. 这轮先解决了什么

这轮首先修的不是算法，而是采样器本身。

前一版失败的根因已经定位清楚：

- 启动 `天纪.exe` 后，桌面上会同时存在多个 `Afx:400000` 顶层窗口
- 旧脚本直接取“第一个主窗口”
- 结果会把旧进程窗口和本次启动窗口混在一起读
- 最终表现就是：
  - 控件写入看起来成功
  - 但输出区域反复吐同一张旧盘

这次的修正是：

- 采样器只绑定“本次启动进程的 PID”
- 只从该 PID 对应的主窗口和子 dialog 读写控件

修完后，定向采样已经不再出现“8 条全是同一盘”的假数据。

## 3. 反推元堂后的核心结论

### 3.1 female / upper-six / ordinary 已经不再是一个“大口袋”

这 6 条样本里，反推元堂后出现了清楚分化：

- `寅时` 3 条：
  - `1984-04-08 03:00`
  - `1930-03-06 03:00`
  - `1930-03-08 03:00`
  - 全部落在 `阳爻池`

- `辰时` 3 条：
  - `1984-04-08 07:00`
  - `1930-03-06 07:00`
  - `1930-03-08 07:00`
  - 全部落在 `阴爻池`

也就是说：

- 对 `阳女 + upper-six + ordinary` 来说，至少 `寅` 和 `辰` 不能再用同一个池规则
- 这已经不是“个别盘偏差”
- 而是一个明确的时位分支

### 3.2 female / lower-six / 水雷屯 已经被坐实是独立分支

`戌时` 的 3 条 `水雷屯` 样本：

- `1930-01-17 19:00`
- `1930-05-03 19:00`
- `1930-10-23 19:00`

它们全部反推出：

- 元堂爻 = `1`
- 且都落在 `阳爻池`

这条结论已经足够强：

- 当前代码里“lower-six 固定阴池”的逻辑，不适用于这组 `水雷屯`
- 它不是单盘特例，而是一个可重复出现的分支

### 3.3 亥时的 `水雷屯` 还暴露了后天卦公式缺口

两条 `亥时` `水雷屯`：

- `1930-10-24 21:00` → `后天卦 = 山地剥`
- `1930-02-01 21:00` → `后天卦 = 地雷复`

这两条用当前 `computeHouTian(...)` 穷举 `1..6` 爻都推不出来。

这说明：

- 问题已经不止是 `getYuanTangDetail(...)`
- 当前 `水雷屯` 的三至尊后天映射，至少对 `亥时` 这组还不完整

所以现在的结构是：

- `戌时水雷屯`：元堂分支已被坐实
- `亥时水雷屯`：连后天卦公式都还有缺口

## 4. 这轮对下一步的直接意义

现在已经可以把“剩余问题”继续拆小：

### A. 元堂层

要优先改的，不再是泛泛的“女性上六时”。

而是更精确的：

- `阳女 + upper-six + ordinary + 寅`
- `阳女 + upper-six + ordinary + 辰`
- `female + lower-six + 水雷屯 + 戌`

### B. 后天卦层

当前 `computeHouTian(...)` 对 `水雷屯` 还差一块：

- `亥时` 这一组的后天卦真值无法由现有 1..6 爻穷举命中

所以如果下一步要开始改代码，顺序应该是：

1. 先修元堂选池规则
2. 再补 `水雷屯@亥` 的后天卦映射
